6. FOUNDATIONAL EXPLANATIONS: PARAMETERS, NEURONS, AND WEIGHTS
======================================================================

Make these distinctions visible in context, not buried in a glossary:

- A PARAMETER is a learned scalar. Most are entries in weight matrices or embedding tables; normalization scale vectors and routers also contain parameters.
- A WEIGHT MATRIX contains many parameters. “8B parameters” does not mean eight billion neurons.
- An ACTIVATION is a value computed for a particular input during a forward pass. It changes when the input changes even when the weights stay fixed.
- A NEURON/UNIT/CHANNEL is a computational coordinate. A transformer has several different widths and intermediate spaces, so there is no single convention-independent total neuron count.
- A TOKEN is a tokenizer unit, not necessarily a word. Token count, residual width, head count, layer count, and parameter count measure different things.
- ATTENTION WEIGHTS are computed mixing coefficients. The learned W_Q, W_K, W_V, and W_O matrices are different objects.
- ROUTING WEIGHTS can refer to learned router parameters or token-dependent mixture coefficients. Name them explicitly to avoid ambiguity.
- An EXPERT here is an FFN inside a decoder block, not a separate full language model or a separate chatbot.
- Standard Qwen3 dense/MoE residual additions and RoPE have no learned scalar weights in the same sense as a linear matrix. Normalization scales are learned.
- A model's units are not individual physical processor cores. Matrices are stored in memory and evaluated by software kernels on hardware.

Include a tiny editable example with input x = [1, 2, 3] and stored W of shape [2, 3]:

y = x W^T = [-0.5, 0.4]

10. DENSE SWIGLU AND THE MEANING OF A GATED CHANNEL
======================================================================

For the normalized FFN input X:

g = SiLU(X W_gate^T)
u = X W_up^T
z = g * u
Y = z W_down^T

SiLU(a) = a * sigmoid(a)

W_gate and W_up: [f,d]
W_down: [d,f]
g, u, z: [B,T,f]
Y: [B,T,d]

17. MEMORY, PRECISION, COMPUTE, AND HARDWARE
======================================================================

Include a calculator driven by the same model profiles. Keep weight storage, KV storage, runtime overhead, and training memory separate.

Raw theoretical weight payload:

weight_bytes = number_of_parameters * bits_per_parameter / 8

Show decimal GB and binary GiB with unambiguous units. For quantization, separate ideal payload from scale/zero-point/block metadata, unquantized tensors, and runtime overhead. A 4-bit estimate is not a guaranteed GGUF or Safetensors file size. Quantization changes numerical representation, not the underlying architecture's parameter count. GGUF is a container format and is not synonymous with one quantization level.

For the ordinary reference models, a simple unquantized KV cache estimate is:

KV_bytes = 2 * B * L * T * Hkv * dh * bytes_per_cached_scalar

At batch one and BF16 cache precision:

- Qwen3-8B: 147456 bytes per token, or 144 KiB; at 32768 tokens, 4.5 GiB.
- Qwen3-30B-A3B: 98304 bytes per token, or 96 KiB; at 32768 tokens, 3 GiB.

Label these as K/V-only estimates excluding allocator overhead, workspaces, and other tensors. Weight precision and cache precision are independent controls. Do not count query heads instead of K/V heads.
